# Construction Automation — hardening candidate\n\n> **Release status: candidate only. Not approved for production or real disbursements.**\n\nConstruction-workflow automation with deterministic compliance gates, contractor/project documentation, three-way invoice/PO/receipt matching, and controlled payment-instruction creation. This repository does not execute bank transfers. Payment instructions remain `PENDING`.\n\n## Security and workflow posture\n\n- Payment registration is downstream of a successful persisted three-way match and a versioned approval decision.\n- The only automated policy route currently modeled is MXN below the configured threshold; it writes durable, tenant-scoped `POLICY/APPROVED` evidence before the payment delegate runs.\n- Requests routed to human review end without an instruction. An authenticated human-approval API/UI has **not** been implemented; do not treat manual approval as operational.\n- The HTTP runtime does not run Flyway as the database owner. Migrations run in a one-shot migrator service; Camunda is configured for schema `camunda`.\n- Procore inbound webhook and offer submission remain disabled/closed until identity, signature, deduplication, and complete processing contracts are implemented.\n- No production credentials, `.env`, database dumps, or generated build output belong in the repository.\n\n## Local verification\n\nRequirements: JDK 21, Maven 3.9.x, Docker Engine with Compose plugin, and a network connection to resolve dependencies.\n\n```bash\nbash -n run.sh test.sh scripts/*.sh\npython3 scripts/verify-hardening-static.py\npython3 scripts/verify-workflow-models.py\nbash scripts/prove-construction-niche.sh\nmvn -B -ntp clean verify\n```\n\nThe Maven test suite uses Testcontainers and therefore needs a working Docker daemon. Static checks are not a substitute for the compile, database, RLS, or Camunda runtime tests.\n\nTo validate Compose configuration with placeholders rather than production values:\n\n```bash\ndocker compose --env-file .env.example config --quiet\ndocker compose --env-file .env.example -f docker-compose.yml -f docker-compose.prod.yml config --quiet\n```\n\nFor a local runtime, copy `.env.example` to `.env` and replace every `REPLACE_WITH_*` value with distinct random development secrets. Never copy production credentials into a workstation `.env` or commit it.\n\n## Production-blocking limitations\n\n1. Build and integration tests must pass on CI with Maven, PostgreSQL/Testcontainers, and the Camunda engine.\n2. The human-approval service for routes `GERENTE` / `COMITE` is not implemented; those routes fail closed.\n3. V20 intentionally refuses a database where legacy Camunda `ACT_%` tables remain in `public`; a reviewed migration is required first.\n4. Real bank transfer, webhook-driven state changes, and external offer submission are not implemented/authorized.\n5. Full migration rehearsal from representative existing data, restore drill, dependency/license review, and deployment rollback test remain required.\n\nSee `GO-LIVE-CHECKLIST.md`, `SECURITY.md`, `PROOF.md`, and `docs/audit/` for the verification contract and blockers.
